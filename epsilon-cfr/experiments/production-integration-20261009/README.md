# CFR本番経路の統合

本番で使わない実験経路と互換APIを削除し、現在のLCFRを構成する責務へ実装を整理しました。比較元は`71acda0`の配布JARです。教師の計算、replayの抽選分布、モデルの構造・パラメータ順序、既定の学習設定は変更していません。

## 実装

- Pivot、専用scalar baseline、snapshot混合方策、旧設定DTO、単独episodeファイル、テスト専用reservoirの本番実装を削除しました。
- 設定は共通`SettingsLoader`から`CfrConfig`へ直接生成します。旧形式の省略項目を補完する経路は削除しました。
- `CfrInputEncoder`がNanoの入力バッチを構築し、`CfrModel`がモデル資源、`CfrLearner`が更新を所有します。Nano教師も推論済み入力から保存用payloadを作り、特徴量を二重に生成しません。
- 収集の出力は`CfrEpisodeSink`へ統一しました。半荘の保存形式は`CfrMatchFile`、replayの内部形式は`CfrReplayCodec`、モデルと実行状態の公開は`CfrRunStore`が担当します。

本番Javaは71ファイル・10,660行から63ファイル・8,873行になりました。旧11クラスを削除し、責務を分離した3クラスを追加しています。フォーマッタを変更Java 66ファイルへ適用し、全リポジトリの参照と生成JARに旧クラスが残らないことを確認しました。過去の実験結果は記録として残しています。

## 学習計算と動作の検証

REGRETとAVERAGEそれぞれについて、同じseedから2更新したモデルと、その旧版checkpointから3更新再開したモデルを比較しました。パラメータ名、重み全体、推論スコア、方策、各更新の損失・勾配ノルムは旧版と新版で完全一致しました。

通常のreactorテスト626件に加え、最終ソースでCFR 144件、共通の並列学習3件、Nano特徴量互換1件を実行し、すべて成功しました。この最終検証にはCPU nativeによる収集・replay登録・学習・評価・保存・再開と、Nano教師の分割バッチ間で観測を保持するテストを含みます。ROCmでは8件が成功し、失敗・skipはありません。テスト選択で除外した9件は実行数へ含めません。

## 収集速度の比較

GPU 0だけを使い、同じ凍結モデル・GRP・TOML・seedで、各プロセス256半荘のwarmup後に4,096半荘を測定しました。実行順は旧版、新版、新版、旧版です。特徴量生成、推論、対局進行、GRP、分岐、圧縮保存、writer終了待ちを測定時間に含みます。モデル読込、warmup、収集後の復号診断は除外します。

測定結果とコマンド、使用したJARのhash、メモリ計測の範囲は[results.json](results.json)に記録しています。各runの速度と、処理件数の合計を時間の合計で割った速度を区別します。同じseedでの比較であり、複数seedの統計評価や長期の対局強度を検証したものではありません。

| 保存込み速度 | 旧版 | 新版 |
| --- | ---: | ---: |
| 1回目の判断/s | 63,500.06 | 62,314.98 |
| 逆順での判断/s | 62,853.01 | 63,055.22 |
| 2回の合算判断/s | 63,174.88 | 62,682.91 |
| 2回の合算半荘/s | 59.2489 | 58.7875 |

合算差は−0.78%です。順番どおりの比較では−1.87%、逆順では+0.32%になりました。この少数回の測定から、統計的な速度の同等性や因果的な退行は断定しません。

各runの主経路は4,096半荘・48,982局・4,367,409判断で一致し、入力形状ごとの件数も一致しました。判断数には順伝播を省略したforced 1,197件を含みます。2回分の追加枝の推論行数は旧版5,418、新版5,167で、非同期の分岐予約による差があります。

メモリの値はプロセス全体を50ms間隔で観測したdevice-wide VRAMとJava RSSです。準備・warmup・収集後の診断を含み、開始時のVRAMにも差があるため、今回の値からモデルのメモリ削減は主張しません。
