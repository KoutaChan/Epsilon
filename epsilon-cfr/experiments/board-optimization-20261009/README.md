# CFRの盤面入力と収集・学習の最適化

CFR固有の行動履歴・局境界系列・GRUを削除し、Nanoと同じ盤面入力と共有の特徴抽出を使う構成へ変更しました。保存待ちによるcollector主スレッドのブロッキングを除き、内部での観測payloadの繰り返し複製を抑えました。

## 測定結果

RX 7900 XTXの同じGPUで各条件を2回完走させました。下表は処理量の合計を実時間の合計で割った値です。[全測定値と適用設定](results.json)を保存しています。

| 処理 | 変更前 | 変更後 | 倍率 |
| --- | ---: | ---: | ---: |
| collector・保存込み | 24,738 decision/s | 33,113 decision/s | 1.34倍 |
| collector・通常局数 | 277.5 局/s | 371.4 局/s | 1.34倍 |
| learner・重複なしの診断 | 3,657 行/s | 9,579 行/s | 2.62倍 |
| learner・通常の重み付き抽選 | 9,359 抽選/s | 30,848 抽選/s | 3.30倍 |
| 同上・重複集約後の実処理 | 1,031 行/s | 3,398 行/s | 3.30倍 |

通常のreplayでは同じ行を複数回抽選します。抽選/sを実処理行/sと取り違えないでください。重複なしの測定は計算性能の診断で、本番の抽選分布を変更する設定ではありません。collectorは4席の通常判断数を数え、追加枝の推論も実時間に含めています。

2回の変更後のcollectorは32,962・33,266 decision/s、重複なしlearnerは9,512・9,647行/sでした。通常の重み付きlearnerは31,144・30,558抽選/sです。

## 比較条件

- 変更前は`ebd2e4b`。双方とも同じNano checkpointの共有表現からREGRETを初期化し、出力はゼロから始めました。旧CFRの学習済み重みを新構造へ変換した比較ではありません。
- hidden 256、BF16設定、pinned転送、学習率`2e-4`、global batch 1,024、microbatch 512を固定しました。
- 収集はHAND_GRP 4,096局、warmup 256局。同じroot bank、GRP、seed、分岐設定を使い、各回の通常判断数は365,147で一致しました。圧縮・fsync・atomic公開・保存終了待ちを含みます。非同期の発行順によって追加枝の推論件数には小さな差があります。
- learnerは同じ4,096エピソード・362,527判断を使用。測定専用の一回限りの変換で旧payloadの履歴部分だけを除き、全件のNano盤面入力が符号化後もbyte単位で一致することを確認しました。行ID、行動、方策、効用、分岐情報と順序は保持しています。互換読み込み機能は本体へ追加していません。
- replayの重み、抽選数、重複集約後の行数、bucket内訳、更新数、checkpoint回数も一致しました。重複なしは64更新・65,536行、重み付きは128更新・131,072抽選・実処理14,438行です。
- learnerには抽選・展開・転送・順逆伝播・optimizer・32更新ごとの保存・GPU完了待ちを含め、warmup、コーパス準備、モデル読込は分離しています。

## 実装

Nanoの状態・候補表現を直接使い、履歴ネットワーク、融合層、系列の転送、隠れ状態cacheを削除しました。後悔と平均方策の出力層、学習目的、LCFRの到達確率補正は維持しています。盤面入力では区別できない過去の行動経路は同じ入力へ集約されるため、完全な本人履歴を使う完全記憶の表形式CFRとは異なる近似です。

`CfrEpisodeSink`が保存先の空き通知を受け、collectorの主スレッドで保存枠を待たないようにしました。未受領の完了エピソードも既存の同時進行枠に数え、新しい対局の補充を抑えます。writerの4本・合計16件の上限、ファイル単位の永続化、エラー伝播は維持しています。

`ObservationPayload`は一度確定した観測を不変のまま予測・判断・教師・保存の間で共有します。観測を確定するときに複製し、内部では不変のまま共有します。可変配列を外部へ渡す場合も独立したコピーを返します。モデルの履歴が不要になったため、共通SPI、Arena、Duel、Reviewerの履歴再構成経路も撤去しました。対局IDと実局序数はモデル入力とは別のメタデータとして保持し、乱数の分離と局単位の方策抽選を維持しています。

GRPの学習・境界評価と、そのための公開局境界は残しています。方策ネットワーク、Arena、Reviewerの推論にはGRPやCFR専用履歴を要求しません。

## 検証と適用範囲

全7モジュールのclean packageと通常テスト909件、追加CPUテスト38件、ROCmテスト8件を通過しました。CPUではNano初期化、REGRET/AVERAGEの学習、保存再開、基準値、配布、両モードのReviewer/Arena、学習全体を確認しました。GPUでは直接/staged推論、BF16、bucket分割と重複集約による損失・勾配・AdamW更新の一致を確認しています。変更したJava 80ファイルにgoogle-java-format 1.28.0を適用しました。

ネットワーク構造と観測payloadの形式が変わるため、旧CFR checkpointやrunは再開できません。Nanoから初期化するか新しいrunで学習してください。測定は独立したディレクトリで実行し、既存の学習runやchampionは変更していません。今回確認したのは実装の動作と速度で、長期学習の強さの改善は未検証です。
