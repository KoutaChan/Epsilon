# CFR 実験記録

比較・診断の記録です。2026-10-08の実験は一時的な実行・診断コードと設定例を削除し、手法・測定条件・結果を残しています。その実行例には、削除前のコミット `79a7530` のソースと当時の入力データが必要です。2026-10-09の性能測定は現行のテスト側benchmarkを使用します。

| 記録 | 主な結果 |
| --- | --- |
| [収集100,000判断/sへの最適化](collection-100k-20261009/README.md) | 保存込み32,768半荘で87,634.0判断/s。同時進行8,192の保存なし診断は108,913.2判断/s（同条件比18.05%改善）。保存込み100kは未確認 |
| [収集80,000判断/sへの最適化](collection-80k-20261009/README.md) | 保存込み77,964.6判断/s。基準比24.38%改善、目標には未達。追加候補の検証を継続 |
| [本番経路の統合](production-integration-20261009/README.md) | 旧実験経路・互換APIを削除。重みと学習再開結果は完全一致、保存込み収集速度の合算差は−0.78% |
| [半荘収集とバッチ構築の最適化](hanchan-optimization-20261009/README.md) | 収集を32,768半荘へ揃え、同じ4,096半荘の比較で判断/sが14.8%改善 |
| [microbatch上限の比較](microbatch-20261009/README.md) | 上限1,024でAVERAGEの実処理行/sが7.1%改善。通常REGRETは上限が作用せず |
| [Learner追加候補と保存処理](learner-refinement-20261009/README.md) | 3候補を検証して不採用。残る固定費としてoptimizerの圧縮保存を特定 |
| [Collector / learnerの最適化](performance-20261009/README.md) | Nanoの共通実行基盤を利用し、同じ標本・保存条件で収集と学習の速度を比較 |
| [Pivot方策の再利用](pivot-reuse/README.md) | Mixtureは有効サンプル数を増やしたが、対戦成績は改善しなかった |
| [凍結状態V baseline](value-baseline/README.md) | 元のNanoの状態Vを使っても、後悔学習後の品質問題は解消しなかった |
| [現在方策と平均方策](policy-diagnosis/README.md) | 現在方策で既に悪化し、平均学習が主因という証拠は得られなかった |
| [後悔学習の原因診断](regret-diagnosis/README.md) | 独立データで後悔予測と行動選択の汎化に問題が見られた |
| [後悔学習の修正比較](regret-repair/README.md)・[全結果](regret-repair/RESULTS.md) | 表現初期化と専用baselineの併用で悪化を抑えたが、初期モデルの強さには届かなかった |

これらは各文書に記載した試行条件での結果です。比較条件を本番の既定動作へ採用した記録ではありません。
