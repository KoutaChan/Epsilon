## 実装

- 収集器から渡す履歴は、判断入力の作成時に一度だけ複製します。外部配列を受け取るコンストラクタの防御コピーは維持し、推論中に盤面を進めない既存の所有権管理を使います。
- 公開イベントは一度符号化し、そのイベントの範囲だけを各席の履歴へ追記します。私有履歴と分岐ごとの独立性は維持します。
- 履歴・局境界を再利用バッファへまとめて書き込み、復号時は保存済みのバイト配列から直接読みます。保存形式、全履歴、語彙・長さ・有限値の検証は維持します。
- learnerは同じ不変の行オブジェクトの復号結果を再利用します。保持量の見積もり64 MiB・最大4,096行の両方で制限し、モデル終了時に解放します。同じ標本IDでも別の行は再復号します。教師値は毎回その行から読み、重み更新に依存するGRU出力はキャッシュしません。

学習率・抽選分布・global batch・microbatch・履歴長・更新回数・精度設定は変更していません。既存の学習runは更新せず、比較用の出力ディレクトリで測定しました。

## 測定条件と再現

[前回と同じTOML](../performance-20261009/cfr.toml)を使用します。収集はHAND_GRP 4,096局、準備実行256局、固定GRPはCPUです。分岐比較、入力生成、推論、対局進行、圧縮、ディスクへの同期、全保存処理の完了待ちを含みます。本番の同梱既定値は32,768局のままです。

learnerの速度測定はREGRETモデルが対象です。同じ保存済みエピソード集合を使い、global batch 1,024、microbatch 512、準備実行8更新としました。通常の重み付き抽出は128更新、重複なし診断は64更新です。抽出・復号・転送・順逆伝播・optimizerと、32更新ごとのチェックポイント保存・GPU完了待ちを含みます。モデル読み込み、リプレイ構築、準備実行は測定時間から分けています。

サーバーの測定ディレクトリは`/home/koutachan/epsilon-ai/benchmarks/cfr-followup-20261009`です。`measure.sh`、`baseline.jar`、`final.jar`、各版のテストクラス、設定、出力を残しています。GPU 0だけを使用し、測定は直列に実行しました。基準版2回、最終版3回、基準版1回の順です。


出力先は未作成の名前を指定してください。元のチェックポイントは変更せず、比較用コピーのメタデータに現行のversion 3と`utilityProfile=TENHOU`を付けています。重みとoptimizerは同じ保存物を使用しました。互換性処理は本番コードに追加していません。最終確定前の`optimized-*`の予備計測は結果から除外しています。

## 検証

- CFR通常テスト142件、CPU nativeテスト13件、GPUテスト9件がすべて成功しました。
- 旧形式とのバイト一致を、空の履歴から100万トークンまで確認しました。破損した長さ、語彙外トークン、非有限値、切断データの拒否も確認しています。
- REGRETとAVERAGEの両方で、キャッシュの有無、同じIDへの別観測・教師の差し替えについて、損失・勾配ノルム・AdamW更新後の全パラメーターがCPUで許容差`1e-7`以内に一致しました。
- GPUではBF16の履歴増分処理、候補数が混在する推論・学習、共通の非同期推論経路を確認しました。キャッシュは両roleで192〜513トークンの系列と同ID差し替えを使い、同じ重み・AdamW状態からの1更新を各6回比較しました。今回の実測は損失差0、更新量の相対L2誤差は最大`1.10e-4`（約0.011%）でした。
- google-java-format、`git diff --check`、Javadoc検証が成功しました。通常ソースに一時ベンチマークやデバッグコードは追加していません。

GPUの追加検証を設計する際、独立した2モデルをBF16で6更新進める比較では、変更前にも変更後にも損失差が既存の1%基準を超えました。この経路は丸め差が後続更新に持ち越されるため、キャッシュの検証は毎回同じ重み・AdamW状態から開始する比較へ分けています。許容差は広げず、CPUでの連続更新の一致検証は維持しました。最初の診断結果も`results.json`に残しています。長期学習軌道のビット単位の一致や棋力の同等性を保証する検証ではありません。
